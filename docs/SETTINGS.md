# Player settings inventory

This inventory covers the browser host, the code linked into its Wasm modules, and the Windows and macOS players shipped with DKC1Recomp v0.0.17. The native reference revision is `559bab62596a97e91f389b39cdeb6cda981ab7c9`. The browser used to hard-code stock video width, mute and presentation behavior, and exposed only Player 1 of the core's two 12-bit input ports. The tables below list the settings surfaced through the Config menu, including settings previously reachable only through a native host, an environment variable or stored profile data. [Revision pins](../upstream.lock.json) · [Browser preferences](../web/settings.js) · [Menu and sheets](../web/index.html)

## Player controls, playback and files

| Config page | Persistent choices and fresh-profile defaults |
| --- | --- |
| Input | Player 1 starts on Keyboard. Player 2 starts disconnected. Each port can select keyboard, controller, both, or disconnected. Each has twelve editable SNES button mappings. Player 1 starts with the arrows for movement, Enter for Start, either Shift for Select, Z/X for B/Y, A/S for A/X and Q/W for L/R. Player 2 keyboard bindings start empty. |
| Input and Devices | Store custom controller profiles, profile-to-device assignments and selected device/profile per port. The built-in Standard mapping is a template. Custom profiles store button, signed-axis or hat bindings including raw index, rest, direction, activation threshold and hat tolerance where applicable. Profile stick deadzone defaults to 0.35. A player can override the deadzone. Device presence and live axis positions come from the Gamepad API. |
| Input and Options | Controller capture mode defaults to automatic. Controller rumble defaults on, subject to an actuator on the chosen gamepad. Keyboard and controller Assist bindings are editable independently. Backspace and the left trigger rewind, Tab and the right trigger fast-forward by default. The remaining Assist shortcuts start unassigned. |
| Options | Pause when inactive defaults on. Appearance follows the system, with light and dark overrides. The stock game variant is the default. The optional Dixie variant uses its separately built Wasm core on load. |
| Sound | Sound starts enabled at 100%. The original soundtrack is the default. The MSU-1 choice selects an imported local music pack on game load. Replacement music gain ranges from 0–4×, initially 1×. Audio drift correction starts enabled. Audio prebuffer selects 1–4 blocks, initially 2, matching the native launch preference. |
| Paths | Remember ROM starts enabled. A retained ROM and the selected local material/music packs are browser storage records. Browser file and folder pickers supply those files. Use each page's import/forget command to change the actual files. |
| Saves | Assist slot 1 of 5 is selected by default. In-game cartridge files use SRAM. Quick states record a running game in a variant-specific slot. Save/Load State and Load/Export Save act on these separate file types. |
| Speed | Normal speed is 1×. The browser offers 2× and 3× playback. Gameplay Assist starts off and gates rewind and held fast-forward. Save and load state, frame advance and the start/pause/resume command can operate with Assist off. |
| Diagnostics | Layer isolation and provenance are video preferences. Record diagnostics starts off. Turning it on records a checkpoint, browser/worker timings and input history for local diagnostics. Taking a capture, advancing a frame and exporting a report are actions. |

Browser input defaults and validation are specified in the [keyboard model](../web/keyboard-profiles.js) and [controller model](../web/gamepad-profiles.js). The native comparison covers the [two-port input packing and Assist resolver](https://github.com/elliotttate/DKC1Recomp/blob/559bab62596a97e91f389b39cdeb6cda981ab7c9/runner/desktop_input.c), [desktop settings fields and persisted host options](https://github.com/elliotttate/DKC1Recomp/blob/559bab62596a97e91f389b39cdeb6cda981ab7c9/runner/windows_platform.c), and the [game loop, audio preroll, saves and rewind](https://github.com/elliotttate/DKC1Recomp/blob/559bab62596a97e91f389b39cdeb6cda981ab7c9/runner/sdl_host.c).

## Video

| Setting | Values, defaults and effect |
| --- | --- |
| Display aspect | Stock 4:3 is the browser default. 16:10 and 16:9 select actual 308×224 and 342×224 core framebuffers. The native desktop default is 16:9. The core decides which scenes can show additional level data. |
| Pixel shape, window size, fullscreen | SNES 7:6 pixels by default or square pixels. Fit is the browser default, with 1×–4× windowed sizes capped to fit. Native starts at 3×. Both start windowed. Fullscreen-on-start is a preference. The fullscreen command uses a browser gesture and the screen alone enters fullscreen. |
| Level edges | Glide by default. Reflect mirrors authored terrain at a wall, Bars blanks the out-of-bounds side, Shift moves the view inward, and Glide spreads that shift over camera travel. |
| Experimental aquatic fixes | Off by default. This one option enables the five upstream switches for pixel boundaries, live scroll, scroll rebase, wall adjacency and wall seams. |
| Phosphor colors | Raw by default, plus CRT, Composite and Trinitron. The native C color lookup transforms a display copy, preserving cartridge output for saves and fingerprints. |
| Display and flat filters | Default Flat and Nearest. Bilinear, Sharp bilinear and Reconstruct are flat-picture options. CRT television selects a separate scanline, beam, glow, halation, mask and composition pipeline. |
| Reconstruction | Sharp pixels, Dither decoding, Diagonal edges, Level-2 slopes (default), Level-3 slopes. Edge strength defaults to 100%, softness to 50%, smooth shading to 60%. |
| CRT presets | Living room by default, Studio monitor, Soft and Custom. A named preset sets all seven tube controls. An individual edit selects Custom. |
| CRT controls | Scanlines, sharpness, mask, mask strength, glow, halation and curvature. Living room starts at 55%, 80%, Fine grille, 30%, 40%, 25%, 50%. Alternative masks are None, Coarse grille and Slot. Fine mask detail and scanlines fade when the viewport has insufficient physical pixels. |
| Frame generation | Off by default. Smooth poses uses the native four-frame lookahead. Smooth poses and motion also supplies the native midpoint between display frames for high-refresh presentation. Emulation and audio keep their original cadence. Pauses, state restores and configuration changes invalidate display history. |
| Diagnostics | Show all layers by default or isolate BG1, BG2, BG3 or objects. The provenance overlay starts off and marks the widened frame's source regions. These changes appear on the next simulated frame. Isolated and diagnostic frames use raw presentation. |
| HD preview | The macOS release provides a separate, approximately 1.62 GiB resident material pack for supported first-level scenes. The web port accepts a user-supplied pack. HD textures, edge cleanup and the grounded finish default off/0%. The effect sliders run on reconstructed 4× frames. Native CPU output and material availability determine room coverage. |

## Storage and platform boundaries

The browser stores player preferences, keyboard configuration and controller configuration locally for the site's origin. Config → Save Config exports their committed values and the remember-ROM preference. Load Config validates the file before applying it. ROM bytes, SRAM, quick-state contents, music and material files have their own storage and transfer commands. A Settings draft becomes persistent when its editor saves it. A new origin or a fresh browser profile has its own settings. [Configuration format](../web/settings.js) · [Browser storage](../web/storage.js)

The native player reads Windows INI sections for graphics, controls, host preferences and paths, and NSUserDefaults on macOS. Environment overrides also cover real settings such as aspect, upscaling, initial ROM, MSU-1 pack/gain and audio preroll. macOS bundles may supply HD preview defaults. Browser equivalents use local settings and imported files. The root launch script supplies a local HTTP origin. A standalone controller JSON remains an input profile import. [Windows preference reader](https://github.com/elliotttate/DKC1Recomp/blob/559bab62596a97e91f389b39cdeb6cda981ab7c9/runner/windows_platform.c) · [macOS graphics reader](https://github.com/elliotttate/DKC1Recomp/blob/559bab62596a97e91f389b39cdeb6cda981ab7c9/runner/macos_pause_menu.m)

Native presenter selection, swapchain latency, display-link selection, monitor refresh negotiation, CPU scheduling and hardware scanout counters depend on OS APIs. The web host uses WebGPU and `requestAnimationFrame`. Browser timestamps measure app submissions and scheduling delays. A screen's verified refresh rate and sustained 120 Hz delivery require measurement on that device. [Native Windows presenter](https://github.com/elliotttate/DKC1Recomp/blob/559bab62596a97e91f389b39cdeb6cda981ab7c9/runner/windows_present.c) · [Browser presentation code](../web/graphics.js)

Recompiler and headless options include execution tracing, breakpoint addresses, fixture inputs, VRAM/PPM/PCM dump paths, forced stalls, smoke-test frame limits, tier-2 manifests and diagnostic-only experimental adapters. These control builds, regression runs and trace output. Core constants such as SRAM size, validated ROM identity, BGRA buffer layout, default stereo sample rate and PPU height form the runtime ABI. Menu selection, held buttons, capture progress, permission grants, current frame, audio queue depth, visibility and active fullscreen are live state. Cheat and NetPlay remain disabled in the browser. [Headless controls](https://github.com/elliotttate/DKC1Recomp/blob/559bab62596a97e91f389b39cdeb6cda981ab7c9/runner/headless_main.c) · [Browser ABI](../runtime/web_core.h) · [Release parity plan](RELEASE_PARITY.md)


## Video verification

At frame 7,450 of the recorded Jungle entry, the stock browser Wasm and pinned native headless host produced the same framebuffer, WRAM, VRAM, CGRAM, OAM, OAM-source and PCM fingerprints independently at both wide resolutions. The full-frame SHA-256 values were `57cab31b8c4a883adf1b257ff4b26a3e7c6d7b551bb389f8e17e331010f93c67` at 308 pixels and `eec274174acc34588a99d514ed57690ffd577883abd057fc75f79b342ceb0f4d` at 342. Four phosphor settings produced four different presentation copies at each width. During 15 additional steps per width, native pose and midpoint generation preserved the raw frame and produced distinct display frames. [Input schedule](../tests/fixtures/jungle-entry.inputs)

The desktop Chrome fullscreen regression reads back submitted WebGPU pixels. It checks the nearest output against every pixel of a synthetic 2× source, compares filters and CRT presets, and checks that HD edge cleanup changes eligible edges and preserves protected ones. It also checks actual fullscreen via Config on wide and compact viewports, 4:3 and both native widescreen sizes, native and square pixel ratios, the retained paused frame, and fullscreen on Start with a local ROM. To run it, use `node scripts/fullscreen_check.mjs --rom "/path/to/your ROM.smc"`. Physical mobile gameplay, hardware scanout timing and full-game widescreen coverage have separate acceptance checks.
